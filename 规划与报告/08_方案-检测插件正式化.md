# 检测插件（path_doctor）正式化改造方案

- 日期：2026-10-26
- 现状：v1.1.0，能跑，但属于"能用的脚本"，不是"正式插件"
- 目标：升级成正式、可交付的运维诊断插件

---

## 一、现状问题（通读后）

1. **命令散**：`/diag path`、`/diag write`、`/diag perm`、`/diag txt` 四个子命令，但语义不清晰，`perm` 和 `write` 有重叠。
2. **`/diag perm` 的跨 uid 验证不可靠**：用 `su nobody`，容器里可能没 su；`setuid` 也依赖 target uid 存在。
3. **没有"共享目录对端可见性"检测**：这正是这次要解决的核心需求——验证 `/AstrBot/data/temp` 是否真的是双向共享、协议端能否读到。
4. **代码冗余**：`pwd`/`os` 重复 import；`_import_plain`/`_import_file` 用延迟导入规避顶层循环，其实直接 import 就行。
5. **class 结构冗余**：`PathDoctor` 类 + `PathDoctorPlugin` 空子类继承，纯属多此一举。
6. **无权限控制**：`/diag` 任何人能调，会暴露路径/账号状态（picacg 就因此做了"私聊或管理员"限制，path_doctor 反而没做）。

## 二、正式化清单

### 1. 命令重组（清爽、语义化）

| 命令 | 作用 | 子命令 |
| --- | --- | --- |
| `/diag` | 总览（路径逐级权限 + 磁盘 + 身份 + 环境） | — |
| `/diag shared` | **检测共享目录对端可见性**（写文件 + 模拟对端读） | `[dir]` 可指定目录，默认 `/AstrBot/data/temp` |
| `/diag writetest` | 目录可写、权限、chmod 后状态 | `[dir]` |
| `/diag report` | 把完整报告写成 txt 发送 | — |

（去掉意义不明的 `perm`，并入 `shared`；`path` 并入默认总览。）

### 2. 新增 `/diag shared` 核心逻辑

这是本次最重要增量。思路：**在指定共享目录下建 `<dir>/path_doctor_probe/` 子目录，写一个带唯一标识的探针文件，chmod 666/777，然后列出该文件的完整权限链 + other-read/other-exec 判断**，让用户一眼看出"协议端到底能不能读到"。

```
/diag shared
→ 共享目录: /AstrBot/data/temp
→ 探针: /AstrBot/data/temp/path_doctor_probe/probe_<ts>.txt
→ 逐级权限: 每级 mode + uid/gid + other-x
→ 文件权限: mode + other-read
→ 结论: ✅ others 可进可读 / ❌ 某级卡住（指出是哪级）
→ 已清理探针
```

> 不能真去"以协议端 uid 读"（不知道协议端具体 uid，也不在同一容器），所以用**权限位 + 逐级目录判定**给出确定结论。这是能做的最准的静态判断。

### 3. 权限控制（正式插件必备）

- 加 `admin_only` 配置（默认 true），非管理员提示"仅管理员可用"。
- 或按 picacg 的做法：敏感输出（账号状态）只在私聊/管理员下显示。

### 4. 代码清理

- 顶部直接 `import pwd`、去掉 `_import_plain`/`_import_file` 延迟导入。
- 删掉 `PathDoctorPlugin` 空子类，`@register` 直接挂在 `PathDoctor` 上。
- 去掉 `_safe_call` 里冗余的 `noqa`，统一异常风格。

### 5. 加 `_conf_schema.json`（正式插件必须有配置面板）

```json
{
  "admin_only": {"type": "bool", "default": true, "desc": "是否仅管理员可用"},
  "shared_dir": {"type": "string", "default": "", "desc": "共享目录（留空=系统 temp）"}
}
```

### 6. metadata 补齐

- `desc` 写明用途
- 加 `support_platforms`、`astrbot_version`（可选但正式插件建议加）

---

## 三、改造范围与分工

- 本插件是"运维工具"，直接在本对话或单独对话改造都行（它不是业务插件，没有独立的产品线目录）。
- 改完后重打 zip（目录包裹 + 显式目录条目，之前已踩过坑），交付。

## 四、验收标准

1. `/diag` → 总览正常
2. `/diag shared` → 在 VM 的共享目录跑，输出"✅ others 可进可读"
3. `/diag report` → 能发 txt
4. 非管理员被拦
5. 无语法错误、无冗余 import、无空子类
